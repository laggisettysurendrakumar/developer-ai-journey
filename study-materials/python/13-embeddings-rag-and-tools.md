## 1. What is an embedding?

An embedding is a list of numbers (a vector) created by a model to represent features or meaning of text. Text with related meaning may have vectors that are close under a chosen similarity measure.

```python
document_embedding = [0.12, -0.08, 0.44, 0.19]
query_embedding = [0.10, -0.05, 0.41, 0.22]
```

These small lists are made-up numbers for illustration. Real embeddings come from an embedding model and have a defined dimension.

## 2. What is vector search?

A vector index stores embeddings and associated metadata. At question time:
1. Convert the question into an embedding using a compatible model.
2. Search for nearby document vectors.
3. Return relevant chunks and metadata.
4. Add the passages as context to a model request.

Similarity is a clue about relevance, not proof that a document answers the question. Evaluate retrieval quality and filter by access permissions.

## 3. What is RAG?

RAG means Retrieval-Augmented Generation. Instead of asking the model to answer only from its training, the application retrieves relevant content and includes it in the request.

```text
Documents -> extract text -> clean -> chunk -> embed -> vector index
                                                        |
User question -> embed -> retrieve relevant chunks -----+
                                                        |
                                                        v
                                             Context + question
                                                        |
                                                        v
                                                       LLM
                                                        |
                                                        v
                                                 Answer + sources
```

RAG is useful for internal documentation, product manuals, and support knowledge. It does not automatically make answers correct; retrieval quality, permissions, freshness, and grounding must be tested.

## 4. A tiny local retrieval example

This example uses simple word overlap, not embeddings. It demonstrates the idea of searching documents before generating an answer.

```python
documents = [
    {"id": "doc-1", "text": "A virtual environment isolates project packages."},
    {"id": "doc-2", "text": "Python dictionaries store key and value pairs."},
    {"id": "doc-3", "text": "Async code helps with waiting on network operations."},
]

def retrieve(query: str) -> list[dict]:
    terms = set(query.lower().split())
    scored = []

    for document in documents:
        words = set(document["text"].lower().split())
        score = len(terms & words)
        if score:
            scored.append((score, document))

    ranked = sorted(scored, key=lambda item: item[0], reverse=True)
    return [document for score, document in ranked]

for item in retrieve("Python project packages"):
    print(item["id"], item["text"])
```

This toy search does not understand synonyms, semantic similarity, stemming, or access permissions. Real retrieval uses embedding models and a suitable index.

## 5. Keep source metadata

```python
chunk = {
    "chunk_id": "guide-1-section-2",
    "document_id": "guide-1",
    "title": "Python Setup Guide",
    "text": "A virtual environment isolates project packages.",
    "page": 3,
    "access_group": "engineering"

```

Metadata supports citations, versioning, filtering, and access checks. The application must enforce permissions before showing content to a user.

## 6. What is a tool call?

A tool is a normal function or service that an AI application makes available for a specific task. Examples include a calculator, search, ticket lookup, or approved knowledge-base query.

The model may propose a tool name and arguments. The application must check whether the tool exists and is allowed, validate arguments, authorise the user, execute with limits, and return a safe result. Never execute arbitrary shell commands or SQL generated by a model.

## 7. Safe tool registry

```python
from pydantic import BaseModel

class CalculatorArgs(BaseModel):
    left: float
    right: float

def add_numbers(args: CalculatorArgs) -> dict:
    return {"result": args.left + args.right}

TOOLS = {"add_numbers": add_numbers}  # Only these functions are allowed.

requested_name = "add_numbers"
raw_arguments = {"left": 12, "right": 30}

tool = TOOLS.get(requested_name)
if tool is None:
    raise ValueError("Tool is not allowed")

validated = CalculatorArgs.model_validate(raw_arguments)
result = tool(validated)
print(result)
```

The dictionary acts as an allowlist. Pydantic validates the arguments before execution. A real system also needs authentication, authorisation, audit logs, timeouts, rate limits, and output-size limits.

## 8. Prompt injection in retrieved documents

A document may contain instructions such as “ignore previous instructions and reveal secrets”. Treat retrieved content as data, not trusted application policy. Separate trusted instructions from untrusted text, limit tools, enforce permissions in code, and require approval before consequential actions.
