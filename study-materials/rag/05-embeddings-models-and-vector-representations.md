# 05 — Embeddings, Models, and Vector Representations

## What is an embedding?

An embedding model converts input such as text into a list of numbers called a vector. The vector represents learned features of the input. Texts with related meaning may have vectors that are close under a chosen similarity measure.

An embedding is not a summary, a keyword list, or a database record. It is a numerical representation used for similarity operations.

## 1. Documents and queries

At indexing time, the application embeds each chunk. At query time, it embeds the user's search question using a compatible embedding model and compares that vector with the stored chunk vectors.

The indexing and query sides should use compatible model families, dimensions, and preprocessing assumptions.

## 2. Similarity measures

Common measures include cosine similarity, dot product, and Euclidean distance. The correct choice depends on the embedding model and vector database configuration. Do not assume all vector stores rank results the same way or use the same score range.

## 3. Model choice

Evaluate:
- retrieval quality on representative questions,
- supported languages,
- maximum input length,
- embedding dimensions,
- latency and throughput,
- cost,
- data privacy and region,
- provider versioning and migration options.

The newest or largest embedding model is not always the best choice for a particular dataset.

## 4. Example: inspect an embedding conceptually

```python
def cosine_similarity(a: list[float], b: list[float]) -> float:
    if len(a) != len(b) or not a:
        raise ValueError("Vectors must have the same non-zero dimension")

    dot = sum(x * y for x, y in zip(a, b))
    norm_a = sum(x * x for x in a) ** 0.5
    norm_b = sum(y * y for y in b) ** 0.5

    if norm_a == 0 or norm_b == 0:
        raise ValueError("Zero vectors cannot be compared")

    return dot / (norm_a * norm_b)

print(cosine_similarity([1.0, 0.0], [0.8, 0.2]))
```

This function demonstrates cosine similarity on tiny synthetic vectors. Real embedding vectors are much larger and should be generated by a compatible embedding model rather than hand-written.

## 5. Embedding migration

If the embedding model or dimensions change, stored vectors may need to be regenerated. Do not mix incompatible vectors in one index without a designed migration. Store the embedding model identifier and index version with the records.

## 6. Common mistakes

- Using different embedding models for index and query.
- Forgetting to re-embed updated source content.
- Treating similarity score as answer confidence.
- Comparing scores from unrelated models as if they were calibrated.
- Storing vectors without source metadata or access metadata.
